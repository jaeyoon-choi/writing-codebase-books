# 강의 작성 지침

강의는 책 전체를 요약하는 5분 강의 하나(`lecture/slides/overview.py`)와 부마다 하나씩인 부별 강의(`lecture/slides/partN.py`)다. 강의 하나는 슬라이드 모듈 하나이고, `lecture/build_lecture.py`가 슬라이드를 그림으로 그리고 대본을 음성으로 바꿔 MP4로 만든다. 각 작성자는 맡은 모듈 하나만 쓴다. 경로의 기준은 책 디렉터리다.

## 1. 맡는 범위

맡은 부와 장은 `book.toml`의 `[layout] order`에서 그 부의 `part` 항목과 다음 `part` 항목 사이의 `ch` 항목이다. 먼저 부 도입(`partN.md`)과 해당 장 전체를 읽는다. 각 장의 "핵심 질문" 상자, "설계 교훈" 상자, 그림과 표를 중심으로 강의를 구성한다.

## 2. 길이와 구성

### 2.1 부별 강의

- 길이는 5~7분이다. 대본은 공백 포함 1,600~2,300자, 슬라이드 9~13장, 단계 18~28개로 맞춘다. 단계 하나의 대본은 한두 문장(공백 포함 220자 이하)이다.
- 첫 슬라이드는 `title_slide(...)`로 만든 제목 슬라이드다. kicker는 "N부 강의", 제목은 부 제목, 부제는 다루는 장, 메모는 "책 『<책 제목>』 N부"처럼 쓴다. 대본 첫 단계에서 이 강의가 다룰 질문을 한 문장으로 말한다.
- 장마다 그 장의 질문, 핵심 구조나 동작, 숫자가 든 예를 보인다. 설계 문서 7절의 예제 시나리오와 그 사건을 이어 쓰면 부와 부가 이어진다.
- 마지막 슬라이드는 정리다. 이 부의 결론을 두세 문장으로 말하고, 다음 부가 무엇을 다루는지 한 문장으로 잇는다(마지막 부는 시리즈를 맺는다).

### 2.2 전체 요약 강의

- 길이는 5분 안팎이다. 대본은 공백 포함 1,800~2,100자, 슬라이드 10~12장, 단계 22~26개로 맞춘다. 맡는 범위는 책 전체이고, 서문, 부 도입, 마지막 장(설계 결정의 대가와 교훈)을 먼저 읽는다.
- 순서는 `work/writing-rules.md`의 문서 오버뷰 순서를 따른다: 제목, 규모를 숫자로 잡는 슬라이드, 시스템이 푸는 문제, 설계 결정(결정마다 한 장), 구성 요소 그림, 대표 동작 흐름, 장애 처리, 설계 교훈, 맺음.
- 제목 슬라이드의 kicker는 "5분 강의", 메모는 "책 『<책 제목>』 N부 M장의 요약"처럼 쓴다. `title_slide`가 표지(`cover.png`가 없으면 `cover.svg`)를 제목 슬라이드에 넣는다.
- 3FS 책의 전체 요약 강의는 슬라이드 11장, 단계 24개, 대본 약 2,000자, 영상 5분 9초였다.

## 3. 모듈 형식

`lecture/example_part.py`(다른 책의 1부 강의 모듈)가 예시다. 모듈은 다음을 정의한다.

```python
from .common import (AMBER, BOOK, CORAL, GRAY, GREEN, NAVY, bookfig, bullets, callout, card, code,
                     flow, note, stat, table, timeline, title_slide)

NAME = "<책 파일 이름>-lecture-part1"   # 출력 파일 이름
KICKER = "<책 제목> · 1부 강의"     # 모든 슬라이드 제목 위의 작은 표시
SLIDES = []
SLIDES.append(title_slide("1부 강의", "<부 제목>", "1장 · 2장", "책 『<책 제목>』 1부", steps=[...]))
SLIDES.append(dict(title="...", html=..., steps=["...", "..."]))
```

- `html`의 요소에 `data-s="N"`을 주면 그 슬라이드의 N단계부터 보인다. `steps[N - 1]`이 N단계가 화면에 있는 동안 읽는 대본이다. 단계 수와 `steps` 길이는 같아야 한다.
- 화면은 1920 × 1080이고 제목은 y = 200 위에 있다. 내용은 y = 230~1000 사이에 둔다. 아래 60px에는 진행 막대와 쪽 번호가 있다.
- 부품(`slides/common.py`의 docstring 참고): `bullets`(목록), `table`(표), `flow`(왼쪽에서 오른쪽으로 가는 상자와 화살표), `timeline`(시간축), `stat`(큰 숫자), `callout`(강조 문장), `card`(제목 있는 상자), `code`(코드 몇 줄), `bookfig`(책의 draw.io 그림), `note`(작은 출처 문장). 필요하면 인라인 SVG를 직접 그려도 된다.
- 책의 그림은 `bookfig("fig-2-1-components.drawio.svg", x, y, w=...)`로 넣는다. 그림 목록은 책의 `figures/`에 있고, 장마다 위치 그림(`fig-N-1-location.drawio.svg`)이 있다. 원래 폭이 680px이므로 900~1100px 폭으로 키우면 읽힌다.
- 글자는 28px 이상으로 둔다. 한 화면의 목록은 다섯 줄 안팎, 표는 여섯 행 안팎으로 둔다.

## 4. 대본 문장

음성 합성(edge-tts, ko-KR-SunHiNeural)이 읽으므로 귀로 들어 이해되게 쓴다.

- 합니다체로 쓰고, 문장은 서술어로 끝낸다.
- 기호를 읽게 하지 않는다. "→", "≤", "~", 괄호, 슬래시를 대본에 넣지 않고 말로 쓴다("60초 이하", "1부터 3까지").
- 단위는 읽히는 말로 쓴다: MiB는 "메비바이트", KiB는 "키비바이트", TiB/s는 "초당 테비바이트", ms는 "밀리초".
- 코드 식별자는 꼭 필요한 것만 쓴다(구성 요소, 프로토콜, 외부 기술의 이름은 써도 된다. 3FS 책에서는 mgmtd, storage, RDMA, CRAQ를 썼다). 함수 이름과 파일 경로는 화면에만 둔다.
- 화면에 보이는 것과 대본이 어긋나지 않게 한다. 대본이 말하는 숫자는 화면에도 있어야 한다.

다음 문장 틀을 쓰지 않는다(`work/writing-rules.md`의 "AI 문장 틀"과 같다).

- 개수를 먼저 예고하고 나열하는 틀: "세 가지를 봅니다", "요구는 셋입니다", "하나는 …이고 다른 하나는 …입니다", 문단 머리의 "첫째, 둘째".
- 강의나 슬라이드가 주어인 메타 서술의 반복: "이 강의는 …를 다룹니다", "이 슬라이드는 …를 보여 줍니다". 첫 단계에서 한 번만 구체적으로 쓴다.
- 추상 비유: 지도, 뼈대, 열쇠, 길, 입구. 기술 용어로 쓴다(책의 부 제목에 이런 말이 있으면 그 제목은 그대로 둔다).
- 문답식 수사와 짧은 단언: "답은 간단합니다.", "여기가 핵심입니다.", "왜 그럴까요?"
- "~라는 것입니다", "~라는 점입니다" 종결의 반복과 문장 첫머리 "그래서"의 연쇄.
- 강조와 과장: "가장 중요한 것은", "핵심은", "바로 이것이".
- 의인화: "mgmtd가 알아서 처리해 줍니다" 대신 "mgmtd가 10초마다 검사해 장애를 판정합니다"처럼 주어와 동사를 쓴다.
- 엠대시(—)는 쓰지 않는다.

슬라이드 제목은 명사구로 쓴다("하트비트 기반 장애 감지", "청크 위치 계산"). 문장형 제목("위치를 저장하지 않는다")과 질문형 제목은 쓰지 않는다.

## 5. 사실의 근거

- 숫자와 사실은 모두 책에서 가져온다. 책에 없는 사실, 추측, 일반론을 더하지 않는다.
- 단계마다 대본 옆에 근거 절을 주석으로 단다. 예: `"...",  # 6.7절 표`.
- 계산값과 측정값을 섞지 않는다. 실측 부록의 값은 "측정한 값"이라고 밝혀 쓴다.

## 6. 확인

- `cd lecture && python3 -I build_lecture.py --lecture <모듈 이름> --preview`로 단계별 PNG를 `build/<모듈 이름>/`에 만든다. 음성과 영상은 만들지 않는다.
- PNG를 Read 도구로 열어 겹침, 넘침, 너무 작은 글자, 화면과 대본의 어긋남을 확인하고 고친다. 몇 장씩 묶어 확인해도 된다.
- 대본 글자 수를 센다: `python3 -I -c "import sys; sys.path.insert(0,'.'); import slides.<모듈 이름> as m; print(sum(len(s) for x in m.SLIDES for s in x['steps']))"`
- 맡은 모듈 외의 파일은 고치지 않는다. 커밋하지 않는다.
