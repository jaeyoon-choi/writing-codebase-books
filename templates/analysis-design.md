# <저장소> 코드 분석 설계

이 문서는 책을 쓰기 전에 만드는 코드 분석 연재의 설계다. 분석 연재는 책의 재료이고, 책 설계(`spec/book-design.md`)의 장 구조와 장마다의 "가져올 것"이 이 연재에서 나온다. 사용자가 이 설계를 승인하기 전에는 분석을 쓰지 않는다.

## 1. 목적과 독자

- 독자: 사용자 본인. 무엇을 이미 알고 무엇을 처음 접하는지 적는다(예: 시스템 프로그래밍에는 능숙하지만 분산 스토리지는 처음). 이 전제가 개념을 어디까지 설명할지를 정한다.
- 목표: 연재를 다 읽은 사용자가 무엇을 설명할 수 있어야 하는가.

## 2. 기준과 범위

- 저장소와 기준 커밋 전체 해시(`book.toml`과 같아야 한다).
- 분석 대상 디렉터리와 대상 밖(빌드 스크립트, 서드파티, 예제 등).
- 1차 자료: 저장소의 설계 문서, 형식 명세, 테스트, 서브모듈 소스. 코드 서술과 대조할 자료를 적는다.

## 3. 편별 범위

0편은 전체 구조와 대표 요청 하나를 끝에서 끝까지 따라가는 개요다. 1편부터는 하위 시스템마다 한 편이다.

| 편 | 다룰 디렉터리 | 이 편이 답할 질문 (3~5개) | 선행 편 |
|---|---|---|---|

## 4. 작업 순서

의존 순서로 쓴다. 0편을 얕게 먼저 쓰고, 마지막 편을 마친 뒤 0편을 갱신한다. 예: `0편 초안 → 1 RPC → 2 전송 → 3 관리 서비스 → … → 0편 갱신`.

## 5. 참고 자료 조사

`references/`에 둘 주제를 적는다: 이 시스템의 논문과 공식 문서, 이 시스템을 평가하거나 실측한 공개 자료, 책의 "다른 시스템의 선택"에서 비교할 시스템.

## 6. 진행 상태

| 편 | 문서 | 검사 0건 | 사용자 확인 |
|---|---|---|---|

기존 분석 자료가 있으면 이 표에 함께 적고, 검사 결과와 고칠 곳을 비고로 남긴다.
